- ブランチ: !`git rev-parse --abbrev-ref HEAD`
- 未 push のコミット: !`git rev-list --count @{u}..HEAD 2>/dev/null || echo '?'`
- このブランチの open な PR: !`gh pr list --head "$(git rev-parse --abbrev-ref HEAD)" --state open --json number,title --jq '.[] | "#\(.number) \(.title)"' 2>/dev/null || echo '(取得できず)'`

PR を着地させてください（$ARGUMENTS。省略時は上の「open な PR」）。CI が緑になるのを待つところから
マージ、マージ後の確認、Issue とドキュメントの後片付け、セッションを閉じるまでが対象です。

**PR を出して終わりにしない。** マージされて、関連する Issue とドキュメントが片付くまでが 1 本です
（AGENTS.md 2-A-10）。

## 1. 前提

上の「open な PR」が空なら、まだ PR が出ていません。先に出してから戻ってください。
**`/land` は PR を作りません。**

`gh` が要ります。入っていない、または認証が切れているときは、その場で言ってください。
`gh auth status` で確かめられます。

## 2. CI が緑になるのを待つ

**`sleep` でポーリングしない。** 待つ手段があるならそれを使う。

```bash
gh pr checks <PR 番号> --watch
```

- 見るのは、その PR で実際に走るチェックだけです。`on: pull_request` で走らないワークフロー
  （main への push だけで走るデプロイ等）をここで待たない。走らないものを待つと永久に終わりません
- このテンプレートの既定では `.github/workflows/tests.yml` の 1 本が走ります

## 3. 赤・コンフリクトのとき

**ここはユーザーを呼んでよい場面です。**

- 自分の変更が原因で直し方が明らかなら、直して push し、2 に戻る
- 判断が要るとき（仕様の選択、他の PR とぶつかる、出力される数値が変わる）は止めて呼ぶ
- **テストの skip・無効化・`--no-verify` で通さない**（AGENTS.md 2-A-3）。落ちる理由のほうを直す
- **PR を閉じて同じ内容で出し直さない。** GitHub は PR を閉じても走っている実行を止めないので、
  同じコミットに対して CI が二重に走ります。直すなら同じ PR に push する
- コンフリクトは既定ブランチを取り込んで解消する。`--force` の push はしない
  （必要なら `--force-with-lease`。ガードは前者だけを止めます）

## 4. マージ

- **緑を確認した SHA をそのままマージする。** 確認のあとに push が入っていないか見ること
- マージ方法はリポジトリの履歴に合わせる。squash なら main の履歴が `<要約> (#番号)` の 1 本になる
- マージしたら、既定ブランチが進んだことを事実で確かめる

```bash
git fetch origin main && git log --oneline origin/main -3
```

## 5. マージ後に何が動いたか

- **デプロイが走る構成なら、走ったことと本番の状態を実測で確かめる。** 「マージしたので
  本番も最新のはず」は確認ではありません
- **走らない PR では「走らない」と言い切る。** ワークフローのパスフィルタ（`paths` /
  `paths-ignore`）から外れる変更だけの PR は、マージしても本番は更新されません
- デプロイの無いリポジトリなら、この節は飛ばしてよい

## 6. 関連 Issue とドキュメント

- Issue に残件があるなら**コメントだけ**残す: 片付いたもの（PR 番号）、残っているもの、次の一手
- 全部終わったらコメントしてからクローズする
- **PR 本文に `Closes #N` を書かない。** マージした瞬間ではなく、**マージ後の確認が済んでから**
  閉じるためです。自動で閉じると、確認していない状態で片付いたことになります
- Issue を閉じたら、一覧や索引に残っている行も消す。**件数の見出し**（「残タスク（全 N 件）」）が
  あるなら数も直す。閉じたのに一覧に残っているのが、いちばん静かに腐ります
- **マージ済みの PR には足せません。** 直すものが出たら小さな追い PR を出し、それも `/land` で着地させる

## 7. セッションを閉じる / 長引いたら切る

- 未 push のコミットを残さない
- **切ってよい条件**: CI の直しが 2 周を超えた、判断待ちでユーザーを呼んだ、会話が長くなって
  1 ターンの入力が膨らんでいる（AGENTS.md 2-A-9）
- 切るときは **PR 番号・どこまで済んだか・次の一手**を 3 行で残す。次のセッションは
  `/land <PR 番号>` から再開できます
