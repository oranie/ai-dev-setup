# ai-dev-setup

AIエージェント（Antigravity, Claude Code等）を用いたソフトウェア開発において、手戻りや当てずっぽうな実装によるトークン浪費を防ぎ、品質を保つための開発環境テンプレートです。

---

## 作成の背景

このリポジトリは、筆者が2週間にわたりAIエージェント（Antigravity 2.0 と Claude Code）を併用してスポーツ予想Webアプリケーションを開発した際の実測データと、そこで発生した不具合・プロンプト課題の分析を基に作成しました。

詳細な開発記と統計データは、以下のブログ記事に記録しています。

- [AI Agentを利用した開発について雑感 - oranie's blog（不具合統計編）](https://oranie.hatenablog.com/entry/2026/09/15/154245)
- [AI Agentを利用した開発におけるプロンプトの重要性やポイントについて - oranie's blog（プロンプト分析編）](https://oranie.hatenablog.com/entry/2026/09/16/120213)

### データと分析根拠

実行トランスクリプト（全28,410ステップ）およびGit履歴から判明した実態です。

> **数値は 2026-09-16 時点のスナップショットです。** 同じ開発を続ければ増え続けるため、
> 規模の目安として読んでください（例: ツール呼び出しはこの時点で 2,403 回、その後 5,485 回まで増えています）。

1. **コードを書く行為は全体の8.3%**:
   全2,403回のツール呼び出し中、ファイルの新規作成・編集は199回（8.3%）でした。残りはシェルでの調査・テスト実行・ログ確認です。
   ただし、**その大半は必要な検証であり、手戻りではありません。** 手戻りの割合は下の分類が示すとおり全体の約28%です。
2. **曖昧な指示による損失（全542件のプロンプト分析）**:
   542件の指示のうち、**51%は手戻りゼロで完了し、手戻りにつながったのは28%（154件）**でした。
   制約やスコープのない曖昧な指示（パターン③）を与えると、AIは都合の良いハルシネーション（未来データ参照、`idx % 6` による捏造計算、assert抜け偽テスト）を生成します。この型の指示は1件あたりの所要時間中央値が18.5分（手戻りなしの4.7倍）、応答ターンが2.1倍に膨張し、95件超のバグを誘発しました。
3. **単文指示による無駄なループ**:
   「全部治ってるの？」（実測34分・78ターン）や「はい続けて」（実測60分・118ターン）のような単文・丸投げ指示により、AIが全件走査や全選択肢の順次実行に走り、大量のトークンを浪費しました。
4. **入力トークン（Token In）の過小評価**:
   1ターン平均約39万トークン（累計20.9億トークン通過）。手戻りが発生するたびに過去履歴とルールが再入力され、コストが急増します。

この損失を防ぐため、本リポジトリでは**「1. Agent側で行うこと」**、**「2. プロンプト自体の品質を高める仕組み」**、
**「3. 大きい出力を本体の会話に持ち込まないこと」**の3つの観点から対策を組み込んでいます。
詳細な設計思想、フロー図、3層防御モデルについては [docs/design/prompt_quality_gate.md](docs/design/prompt_quality_gate.md) に記録しています。

## 観点1: Agent側で行うこと（自律抑止・自己点検・物理ガード）

人間が常に完璧な指示を出すことは困難です。そのため、曖昧な指示が入力された場合でも、エージェント側が推測で走らずに自律してブレーキをかけ、品質を担保する仕組みを設けています。

### 1. 推測による即座実行（Eager Execution）の禁止と門前チェック (`AGENTS.md`)
エージェントが指示を受け取った際、直ちにコード生成やコマンド実行に入らず、以下の**5大受入基準（Definition of Input: DoI）**を照合します。
- **スコープの特定**: 対象ファイル・ディレクトリが名指しされているか（「全部」「あれ」は保留）。
- **ドメイン制約・フォールバック**: 未来データ除外、欠損値処理（NaN等）、按分ルールが指定されているか。
- **新規技術のリファレンス**: `docs/references/` に公式調査メモが存在するか。
- **完了条件（DoD）の明示**: 期待される具体的な戻り値アサーションやCI通過基準が明確か。
- **選択の丸投げ検知**: 直前の選択肢に対し「続けて」「まかせる」と返された場合、全件実行せず番号確認を行う。

基準未達時は作業を保留し、**ユーザーが番号で選択できる形式で逆質問**を行います。

### 2. 計画承認モードへの強制引き上げ
以下の条件に合致する場合、エージェントはコード生成を行わず、必ず実装計画書（`implementation_plan.md`）を作成してユーザー承認を得ることを義務付けています。
- 変更対象が 3 ファイル以上に跨がる場合
- 外部ライブラリ、クラウドインフラ（GCP等）、CI/CDワークフローの設定変更
- 出力される数値や判定結果が変わる変更（集計ロジック、スコアリング、評価基準）

### 3. 禁止・遵守事項の徹底 (`AGENTS.md`)
実際に起きた不具合に基づく絶対ルールです。**すべてのプロジェクトに適用するもの**と、
**該当する場合だけ適用するもの**に分けてあります（関係しない節は削除して構いません）。

共通:
- 配線抜けの防止（末端の処理関数までデータが届いている割合をテストで確認）
- 値の捏造の厳禁（`idx % 6` や固定値でのスコア生成禁止。無いものは欠損か中立値）
- 形骸化テストの防止（具体的な戻り値のassertを義務付け。**テストの skip / 無効化も禁止**）
- 起動処理とデプロイ時の安全性（起動は数秒で完了。**やることが無ければ書き込みを行わない**）
- **定義を2箇所に置かない**（やむを得ない場合は一致をテストで縛る）
- Git安全運用（`git add -A` / `git add .` の禁止、`--force` ではなく `--force-with-lease`）
- **PRの時点でテストが走る構成にする**（既定ブランチへのpushでしか走らないと、落ちるのは常にマージ後）
- **測ってから入れる・外す**（良くならなければ入れない。測った数値を残す）

該当する場合:
- 時系列データ・予測処理を扱う場合: 未来データの参照防止
- Webフロントエンドを含む場合: CSS `!important` 新規追加禁止、`alert` / `confirm` 禁止

### 4. 提出前自己点検チェックリスト（パターン⑤対策）
指示に不備がない場合でも発生する手戻り（環境差、本番競合、生成物の初歩的破綻）を防ぐため、完了報告前にエージェント自身で以下を点検します。
- **実行環境差**: 新規importがロックファイルに存在するか、ローカル環境固有の依存がないか。
- **起動シーケンス**: 変更が起動経路に影響を与えていないか、新旧コンテナ重複時にSQLite競合が起きないか。
- **生成物の整合性**: 出力した画面やレポートに、項目の取り違え・単位の不一致・値の重複といった初歩的な破綻がないか。
- **原因を推測で報告しない**: 失敗の原因はログか再現で確かめてから断定する。推測のまま直すと、無関係な箇所を壊したうえで再発する。

### 5. ライフサイクルフックによる物理ガード
**Antigravity と Claude Code の両方**で、危険なコマンドを実行前に遮断します。

| エージェント | 設定ファイル | 遮断のしかた |
|---|---|---|
| Antigravity | `.agents/hooks.json` | `PreToolUse` で `decision: deny` を返す |
| Claude Code | `.claude/settings.json` | `PreToolUse` で終了コード2と理由を返す |

- **判定は `guards/rules.py` の1箇所にあり、両者が同じ表を読みます。** ルールを足すときはここだけを直します
  （`tests/test_hook_wiring.py` が、2つのエージェントの判断が食い違わないことと、設定が指すスクリプトが実在することを縛ります）
- 遮断するもの: 一括ステージング、ステージしていない差分のコミット、`--force` push、`rm -rf`、
  `git clean -fd` / `reset --hard`、検証の飛ばし（`--no-verify`）、ブロックデバイスへの書き込み
- **`--force-with-lease` は通します。** squash マージ後にブランチを作り直す運用で必要になるため
- 本当に必要なときは、コマンドの先頭に `AI_DEV_ALLOW_DESTRUCTIVE=1` を付けると通ります（何を許したかが記録に残ります）
- **`PreInvocation` ガード**（Antigravity）: モデル推論開始の直前に、5大受入基準（DoI）のリマインダーを自動注入し、推測による暴走を抑制。

## 観点2: プロンプト自体の品質を高める仕組み（入力支援・テンプレート・短縮記法）

指示を出す側（人間）が迷わず、負担なく高品質なプロンプトを作成できる環境を整備しています。

### 1. 5大受入基準を満たすタスク別テンプレート (`docs/prompts/templates.md`)
迅速完結（パターン①）の共通項を抽出した定型フォーマットです。
- **新機能追加・改修**: スコープ境界、入力データ、ドメイン制約、例外時按分ルール、テスト要件。
- **データ集計・予測ロジック**: 基準日時境界、目的変数以外の事後スタッツ除外、欠損値ポリシー、到達率アサーション。
- **インフラ・CI/CD設定**: 事前調査の義務付け、最小権限、起動性能、`.dockerignore` 更新。
- **完了確認・不具合修正**: 「全部治ってるの？」を排除し、確認対象の具体的項目列挙と副作用検証を指示。

### 2. モバイル・短文入力支援 (`docs/prompts/mobile_guide.md`)
スマホや移動中の操作で長文が打てない場合でも、エージェントを暴走させないための運用ルールです。
- **スラッシュコマンド（ショートコード）**:
  - `/fix [対象] [現象]`: 影響範囲調査メモを作成し修正案を1つ提示
  - `/feat [機能名]`: リファレンス調査と計画書（DoD付き）を作成
  - `/verify [対象]`: 単体テスト・起動確認を実行してログを要約
  - `/triage`: 課題一覧を優先度順に番号付きで提示
- **タグ付き短縮構文**:
  - `[調査] <対象>`
  - `[修正:スコープ限定] <ファイル> <要件>`
  - `[確認:項目限定] <項目A, 項目B>`
- **番号選択プロトコル**:
  - AIからの逆質問や選択肢提示に対し、「続けて」「了解」ではなく「1」と番号で回答するルールを徹底。

### 3. 技術情報の先行蓄積基盤 (`docs/references/`)
コードを書く前に公式マニュアル、GitHub、技術記事を調査し、`docs/references/template.md` を用いてMarkdownで記録します。
正確なシグネチャ、設定値、IAM権限をエージェント間で引き継ぎ、記憶や当てずっぽうによる試行錯誤を根絶します。

## 観点3: 大きい出力を本体の会話に持ち込まない（委譲）

モデルへの入力は毎ターン全履歴が送り直されます。テストの全件出力を 1 回会話に載せると、
**そのセッションの残り全部のターンで再送**されます。1 ターン平均 39 万トークンという実測値の
中身は、ここに積もったものです。

対処はツールによって変わります。共通の原則は `AGENTS.md` 2-A-9 に置き、実装は分けています。

| ツール | どうするか |
|---|---|
| Claude Code | `.claude/agents/` のサブエージェントへ委譲する。会話履歴を引き継がない別コンテキストで動くので、生ログは向こうに閉じ、要約だけが返る |
| Antigravity | 同等の仕組みが無い。**文脈の圧縮はハーネスに任せ**、出力の絞り込みとスクラッチの隔離だけを守る（`GEMINI.md` 1-3） |

委譲先は 5 本です。線は **「コードを生成するかどうか」**。

| agent | モデル | 何を任せるか |
|---|---|---|
| `test-runner` | `claude-sonnet-5` | テスト・検証の実行。落ちたものだけ返す |
| `repo-scout` | `claude-sonnet-5` | コードの在処探し。パスと行番号だけ返す |
| `reference-surveyor` | `claude-sonnet-5` | 公式ドキュメント調査と `docs/references/` への記録 |
| `implementer` | `claude-opus-5` | プラン通りのコード生成（テスト追加を含む） |
| `implementer-lite` | `claude-sonnet-5` | 決まった実行、文書の修正、定数・閾値の書き換え |

- **本体が高いモデル（Fable 5.1 など）のときほど効きます。** 計画・判断・レビューだけを手元に残し、
  決まった実行と範囲の決まった実装を出します。本体が Sonnet のときは、この理由での委譲は効きません
- **委譲は無料ではありません。** 向こうは規約を読み直すところから始まるので、軽い作業では
  往復のほうが高くつきます。目安は「出力が数百行を超えるか」
- **本番操作・PR・マージは委譲しません。** 取り返しがつかないものは手元に残します
- `PostToolUse` フック（`.claude/hooks/big_output.py`）が、大きい出力を本体で受けた直後に
  「次は向こうへ投げる」と知らせます。**止めはしません**
- `model:` をエイリアス（`sonnet`）で書くとプロバイダによって世代が変わるため、フル ID で固定し、
  `tests/test_subagents.py` で縛っています

設計と理由は [docs/design/subagents.md](docs/design/subagents.md) に記録しています。

## 使い方

新しいWebアプリケーションやデータパイプラインの開発を開始する際、本リポジトリをテンプレートとして利用します。

GitHub の **Use this template** から新しいリポジトリを作るのが最も簡単です
（このリポジトリの履歴を引き継がずに始められます）。手元へ持ってくる場合:

```bash
# 1. テンプレートを取得する（履歴を引き継がない）
git clone --depth 1 https://github.com/oranie/ai-dev-setup.git my-new-project
cd my-new-project && rm -rf .git && git init

# 2. ガードが動くことを確認する
python3 -m unittest discover tests

# 3. 自分のプロジェクトに合わせて削る
#    AGENTS.md 第2章の「2-B. 該当する場合に適用する」から、関係しない節を削除してください。
#    規約は短いほど守られます。

# 4. 開発の開始
#    Antigravity / Claude Code を起動すると AGENTS.md / GEMINI.md / CLAUDE.md が読み込まれ、
#    危険コマンドのフックが有効になります。
#    指示を出す際は docs/prompts/templates.md や mobile_guide.md を活用してください。
```

### ガードが効いているかを確かめる

フックは**見つからなくても黙って素通りする**ため、最初に一度だけ確認しておくことを勧めます。

```bash
python3 -m unittest tests.test_hook_wiring -v
```

設定ファイルが指すスクリプトが実在すること、2つのエージェントで判断が食い違わないことを確認します。
