# ai-dev-setup

AIエージェント（Antigravity, Claude Code等）を用いたソフトウェア開発において、手戻りや当てずっぽうな実装によるトークン浪費を防ぎ、品質を保つための開発環境テンプレートです。

---

## 作成の背景

このリポジトリは、筆者が2週間にわたりAIエージェント（Antigravity 2.0 と Claude Code）を併用してスポーツ予想Webアプリケーションを開発した際の実測データと、そこで発生した不具合・プロンプト課題の分析を基に作成しました。

詳細な開発記と統計データは、以下のブログ記事に記録しています。

- [AI Agentを利用した開発について雑感 - oranie's blog（不具合統計編）](https://oranie.hatenablog.com/entry/2026/09/15/154245)
- [AI Agentを利用した開発におけるプロンプトの重要性やポイントについて - oranie's blog（プロンプト分析編）](https://oranie.hatenablog.com/entry/2026/09/16/120213)

### データと分析根拠
全28,410ステップの実行トランスクリプトおよびGit履歴から判明した実態です。

1. **コードを書く行為は全体の8.3%**:
   全2,403回のツール呼び出し中、コード生成は199回（8.3%）にすぎず、残りの9割以上はシェルコマンドでの調査・検証や手戻り修正に費やされていました。
2. **曖昧な指示による甚大な損失（全542件のプロンプト分析）**:
   制約やスコープのない曖昧な指示（パターン③）を与えると、AIは都合の良いハルシネーション（未来データ参照、`idx % 6` による捏造計算、assert抜け偽テスト）を生成しました。結果として1件あたりの所要時間中央値が18.5分（正常完結の4.7倍）、応答ターンが68.4ターン（2.1倍）に膨張し、95件超のバグを誘発しました。
3. **単文指示による無駄なループ**:
   「全部治ってるの？」（実測34分・78ターン）や「はい続けて」（実測60分・118ターン）のような単文・丸投げ指示により、AIが全件走査や全選択肢の順次実行に走り、大量のトークンを浪費しました。
4. **入力トークン（Token In）の過小評価**:
   1ターン平均約39万トークン（累計20.9億トークン通過）。手戻りが発生するたびに過去履歴とルールが再入力され、コストが急増します。

この損失を防ぐため、本リポジトリでは**「1. Agent側で行うこと」**と**「2. プロンプト自体の品質を高める仕組み」**の2つの観点から総合的な対策を組み込んでいます。

---

## 観点1: Agent側で行うこと（自律抑止・自己点検・物理ガード）

人間が常に完璧な指示を出すことは困難です。そのため、曖昧な指示が入力された場合でも、エージェント側が推測で走らずに自律してブレーキをかけ、品質を担保する仕組みを設けています。

### 1. 推測による即座実行（Eager Execution）の禁止と門前チェック (`AGENTS.md`)
エージェントが指示を受け取った際、直ちにコード生成やコマンド実行に入らず、以下の**5大受入基準（Definition of Input: DoI）**を照合します。
- **スコープの特定**: 対象ファイル・ディレクトリが名指しされているか（「全部」「あれ」は保留）。
- **ドメイン制約・フォールバック**: 未来データ除外、欠損値処理（NaN等）、按分ルールが指定されているか。
- **新規技術のリファレンス**: `docs/references/` に公式調査メモが存在するか。
- **完了条件（DoD）の明示**: 期待される具体的な戻り値アサーションやCI通過基準が明確か。
- **選択の丸投げ検知**: 直前の選択肢に対し「続けて」「まかせる」と返された場合、全件実行せず番号確認を行う。

基準未達時は作業を保留し、**ユーザーが番号で選択できる形式で逆質問**を行います。

### 2. 計画承認モードへの強制引き上げ
以下の条件に合致する場合、エージェントはコード生成を行わず、必ず実装計画書（`implementation_plan.md`）を作成してユーザー承認を得ることを義務付けています。
- 変更対象が 3 ファイル以上に跨がる場合
- 外部ライブラリ、クラウドインフラ（GCP等）、CI/CDワークフローの設定変更
- 予測モデルの特徴量抽出・評価ロジックの変更

### 3. 7大禁止・遵守事項の徹底 (`AGENTS.md`)
過去の83件の不具合実績に基づく絶対ルールです。
- 未来データの参照防止（`match_datetime` 以前のデータ限定、対戦カード日時完全一致照合）
- 配線抜けの防止（末端処理関数での有効データ実到達率テストを必須化）
- ダミー採点・捏造数式の厳禁（`idx % 6` や固定値でのスコア生成禁止）
- 形骸化テストの防止（例外検知だけでなく具体的な戻り値assertを義務付け）
- 起動性能の担保（Webアプリ起動は5秒以内、ヘルスチェック前の全件DBスキャン禁止、SQLite一括書き込みはバッチ分離）
- UIアンチパターン防止（CSS `!important` 新規追加禁止、`alert` / `confirm` 禁止）
- Git安全運用（`git add -A` や `git add .` の禁止、対象ファイルの明示ステージング）

### 4. 提出前自己点検チェックリスト（パターン⑤対策）
指示に不備がない場合でも発生する手戻り（環境差、本番競合、生成物の初歩的破綻）を防ぐため、完了報告前にエージェント自身で以下を点検します。
- **実行環境差**: 新規importがロックファイルに存在するか、ローカル環境固有の依存がないか。
- **起動シーケンス**: 変更が起動経路に影響を与えていないか、新旧コンテナ重複時にSQLite競合が起きないか。
- **ドメイン整合性**: 画像やUIの出力項目に初歩的な破綻（選手欄にチーム名が入る、投手と野手の指標混同等）がないか。

### 5. ライフサイクルフックによる物理ガード (`hooks.json`)
- **`PreToolUse` ガード**: `git add -A` や `git add .`、`git commit -am`、`rm -rf /` 等の危険コマンドをプロセス実行前に強制遮断（`decision: deny`）。
- **`PreInvocation` ガード**: モデル推論開始の直前に、5大受入基準（DoI）のリマインダーをシステムメッセージとして自動注入し、推測による暴走を抑制。

## 観点2: プロンプト自体の品質を高める仕組み（入力支援・テンプレート・短縮記法）

指示を出す側（人間）が迷わず、負担なく高品質なプロンプトを作成できる環境を整備しています。

### 1. 5大受入基準を満たすタスク別テンプレート (`docs/prompts/templates.md`)
迅速完結（パターン①）の共通項を抽出した定型フォーマットです。
- **新機能追加・改修**: スコープ境界、入力データ、ドメイン制約、例外時按分ルール、テスト要件。
- **データ集計・予測ロジック**: 基準日時境界、目的変数以外の事後スタッツ除外、欠損値ポリシー、到達率アサーション。
- **インフラ・CI/CD設定**: 事前調査の義務付け、最小権限、起動性能、`.dockerignore` 更新。
- **完了確認・不具合修正**: 「全部治ってるの？」を排除し、確認対象の具体的項目列挙と副作用検証を指示。

### 2. モバイル・短文入力支援 (`docs/prompts/mobile_guide.md`)
スマホや移動中の操作で長文が打てない場合でも、エージェントを暴走させないための運用ルールです。
- **スラッシュコマンド（ショートコード）**:
  - `/fix [対象] [現象]`: 影響範囲調査メモを作成し修正案を1つ提示
  - `/feat [機能名]`: リファレンス調査と計画書（DoD付き）を作成
  - `/verify [対象]`: 単体テスト・起動確認を実行してログを要約
  - `/triage`: 課題一覧を優先度順に番号付きで提示
- **タグ付き短縮構文**:
  - `[調査] <対象>`
  - `[修正:スコープ限定] <ファイル> <要件>`
  - `[確認:項目限定] <項目A, 項目B>`
- **番号選択プロトコル**:
  - AIからの逆質問や選択肢提示に対し、「続けて」「了解」ではなく「1」と番号で回答するルールを徹底。

### 3. 技術情報の先行蓄積基盤 (`docs/references/`)
コードを書く前に公式マニュアル、GitHub、技術記事を調査し、`docs/references/template.md` を用いてMarkdownで記録します。
正確なシグネチャ、設定値、IAM権限をエージェント間で引き継ぎ、記憶や当てずっぽうによる試行錯誤を根絶します。

## ディレクトリ構成

```text
ai-dev-setup/
├── AGENTS.md                  # エージェント共通行動規範（DoI、Eager Execution禁止、7大ルール）
├── GEMINI.md                  # Antigravity向け設定（計画引き上げ、DoI適用、監査スキル）
├── CLAUDE.md                  # Claude Code向け設定（DoI適用、自己点検、番号選択式逆質問）
├── .gitignore                 # 認証情報・生データ・キャッシュの誤コミット防止
├── .dockerignore              # ビルドコンテキスト肥大化防止（467MB事故事例の再発防止）
├── docs/
│   ├── prompts/               # 【観点2】プロンプト品質向上ガイド
│   │   ├── templates.md       # タスク別（機能追加・機械学習・CI設定）テンプレート
│   │   └── mobile_guide.md    # ショートコードおよびモバイル短縮記法ガイド
│   └── references/            # 【観点2】技術調査結果の蓄積保管庫
│       ├── README.md          # 運用ルールと命名規約
│       └── template.md        # 公式URL・API構文・IAM権限・落とし穴を記録する雛形
├── .agents/
│   ├── hooks.json             # 【観点1】ライフサイクルフック定義（PreToolUse / PreInvocation）
│   ├── hooks/
│   │   ├── pre_tool_guard.py  # git add -A 等の危険コマンドを遮断するスクリプト
│   │   └── pre_invocation_checker.py # 5大受入基準（DoI）を推論前に注入するスクリプト
│   └── skills/
│       ├── reference-survey/   # 実装前のリファレンス先行調査スキル
│       ├── leak-and-wiring-audit/ # データリーク・配線抜け監査スキル
│       └── code-quality-audit/ # 形骸化テスト・CSS・インフラ監査スキル
└── tests/
    ├── test_pre_tool_guard.py # コマンドガードの単体テスト
    └── test_pre_invocation_checker.py # 門前チェックフックの単体テスト
```

## 使い方

新しいWebアプリケーションやデータパイプラインの開発を開始する際、本リポジトリをテンプレートとして利用します。

```bash
# 1. テンプレートのクローン
git clone https://github.com/oranie/ai-dev-setup.git my-new-project
cd my-new-project

# 2. ガードスクリプトのテスト実行（全8件パスすることを確認）
python3 -m unittest discover tests

# 3. 開発の開始
# Antigravity または Claude Code を起動すると、自動的に AGENTS.md / GEMINI.md / CLAUDE.md が読み込まれます。
# 指示を出す際は docs/prompts/templates.md や mobile_guide.md を活用してください。
```
