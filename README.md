# ai-dev-setup

AIエージェント（Antigravity, Claude Code等）を用いたソフトウェア開発において、手戻りや当てずっぽうな実装によるトークン浪費を防ぎ、品質を保つための開発環境テンプレートです。

---

## 作成の背景

このリポジトリは、筆者が2週間にわたりAIエージェント（Antigravity 2.0 と Claude Code）を併用してスポーツ予想Webアプリケーションを開発した際の実績と、そこで発生した不具合の分析結果を基に作成しました。

詳細な開発記と統計データは、以下のブログ記事に記録しています。

- [AI Agentを利用した開発について雑感 - oranie's blog](https://oranie.hatenablog.com/entry/2026/09/15/154245)

初期の動くプロトタイプを作成する段階（60〜70点レベル）は2日ほどで進みましたが、その後の運用を見据えた品質向上と整備には約2週間を要しました。開発の過程でAIエージェントは自律的に修正を繰り返したものの、同じ箇所でエラーと修正を繰り返してトークンを消費し続ける事態が多発しました。

この経験から、AIにいきなり「この機能を実装して」と命令するのではなく、**「実装に着手する前に公式マニュアル、GitHubリポジトリ、技術ブログを調査し、技術メモとして蓄積してからコードや設定ファイルを生成させる」** プロセスを仕組みとして組み込む必要があると判断し、本テンプレートを整備しました。

## データと分析根拠

本テンプレートの規約と仕組みは、実際の開発トランスクリプト（全28,410ステップ）およびGit履歴から抽出した以下の実測値に基づいています。

### 1. 開発活動の内訳（コード生成は全体の8.3%）
AIエージェントが実行した全2,403回のツール呼び出しの内訳です。

- シェルコマンド実行（調査・検証・テスト）: 1,747回 (72.7%)
- GitHub / リモート操作: 248回 (10.3%)
- ファイル部分修正: 151回 (6.3%)
- ファイル新規作成: 48回 (2.0%)
- その他（タスク管理、閲覧、通知等）: 209回 (8.7%)

コードを書く行為（新規作成48回＋部分修正151回＝199回）は、全体のわずか8.3%でした。残りの9割以上は、手元でのテスト実行、Gitログ解析、ファイル構造やログの調査といった検証作業と手戻り修正に費やされていました。

### 2. 不具合・ハルシネーション統計（全83件）
246コミット、65件のPull Requestを通じて特定された課題の分類です。

| 分類 | 主な発生事象 |
| :--- | :--- |
| **未来データ参照（データリーク）** | 確定スコアが逆算して特徴量に混入し「的中率98%」と誤判定。未開催カードに対して前年の同名大会結果を照合。 |
| **幽霊コード・配線抜け** | 過去27万件の実績データを取り込んだが末端の評価関数に渡っておらず、全選手の89%で空のまま予測が動作。 |
| **ダミー採点（捏造数式）** | 選手の能力値を実績から計算せず、`base = 96.0 - (idx % 6) * 1.5`（登録番号の剰余）で機械的に捏造。過去データのない新鋭選手を機械的に最下位扱い。 |
| **形骸化テスト** | `assert` 文を含まず、例外が出ないことだけを確認する偽テストの生成。テスト自体が未来データを参照してパスする偽装。 |
| **インフラ・起動障害** | Cloud Run上で複数コンテナから単一SQLiteへ同時書き込みしてDB破損。起動時の全件スキャンによるヘルスチェック超過（4分）。.dockerignore不備によるビルドコンテキスト467MBへの肥大化。 |
| **UIアンチパターン** | CSSにおける `!important` の濫発。ブラウザ標準 `alert` / `confirm` の呼び出し。モバイル幅（375px）での意図しない横スクロール。 |
| **セキュリティ・誤操作** | `git add -A` による作業領域の認証トークンファイルの誤コミット。クラウド権限（IAM）の当てずっぽうな推測による403エラー連発（3回目で実測解決）。 |

### 3. 入力トークン（Token In）の構造
- 1ターンあたりの平均入力: 約39万トークン
- セッション累計: 約20.9億トークンが通過（出力の約514倍）
- 事前推計（3万〜10万トークン）の約1桁上

毎回のリポジトリルール、会話履歴、直前のコマンド標準出力が再入力される構造上、手戻りやログの垂れ流しが発生すると入力トークンが急速に膨張します。

## 本リポジトリの構成と対策

上記の課題を根本から防ぐため、以下の構成を整えています。

```text
ai-dev-setup/
├── AGENTS.md                  # エージェント共通の行動規範・7大禁止遵守事項
├── GEMINI.md                  # Antigravity向け設定（監査スキル活用・トークン抑制）
├── CLAUDE.md                  # Claude Code向け設定（事前調査メモ化・テスト品質）
├── .gitignore                 # 機密情報・生データ・キャッシュの誤コミット防止
├── .dockerignore              # ビルドコンテキスト肥大化防止（467MB事故事例の再発防止）
├── docs/
│   └── references/            # 技術調査結果の蓄積保管庫
│       ├── README.md          # 運用ルールと命名規約
│       └── template.md        # 公式URL・API構文・IAM権限・落とし穴を記録する雛形
├── .agents/
│   ├── hooks.json             # コマンド実行前ガードフック定義
│   ├── hooks/
│   │   └── pre_tool_guard.py  # git add -A や破壊的コマンドをブロックするスクリプト
│   └── skills/
│       ├── reference-survey/   # 実装前のリファレンス先行調査スキル
│       ├── leak-and-wiring-audit/ # データリーク・配線抜け監査スキル
│       └── code-quality-audit/ # 形骸化テスト・CSS・インフラ監査スキル
└── tests/
    └── test_pre_tool_guard.py # ガードスクリプトの単体テスト
```

## 中核となる仕組み

### 1. リファレンス先行（Reference-First）
コードや設定ファイルを書き始める前に、対象技術の公式マニュアル、GitHub公開リポジトリ、信頼できる技術ブログを調査し、`docs/references/` 配下にMarkdownで記録することを義務付けています。
正確なシグネチャ、設定値、必要なIAM権限を確認した上で計画を立てるため、当てずっぽうな実装による試行錯誤ループを削減します。

### 2. 7大禁止・遵守事項 (`AGENTS.md`)
- **未来データの参照防止**: `match_datetime` 等のイベント発生前データのみ使用。対戦カード照合は開催日時の完全一致を必須化。
- **配線抜けの防止**: 新規データソース追加時は、末端処理関数での実到達率（全対象に対する有効データの割合）をテストコードでアサーション。
- **ダミー採点・捏造数式の厳禁**: `idx % 6` や固定値でのスコア捏造を禁止。欠損時は `NaN` または妥当な初期値分布を適用。
- **形骸化テストの防止**: 具体的な戻り値に対する `assert` を必須化し、例外が出ないだけを確認するテストを禁止。
- **インフラ・起動性能の担保**: Webアプリ起動処理は5秒以内（ヘルスチェック前の全件DBスキャン禁止）。SQLite一括書き込みはバッチワーカーへ分離。
- **UIアンチパターン防止**: CSS `!important` の新規追加厳禁。`alert` / `confirm` の禁止。
- **Git安全基準**: `git add -A` や `git add .` の禁止。変更ファイルを明示してステージング。

### 3. ライフサイクルフックによる物理ガード (`hooks.json`)
Antigravityの `PreToolUse` フックを利用し、エージェントがシェル上で `git add -A` や `git add .`、`git commit -am`、`rm -rf /` 等を実行しようとした場合、プロセスの実行前段階で強制ブロック（`decision: deny`）します。

## 使い方

新しいWebアプリケーションやデータパイプラインの開発を開始する際、本リポジトリの内容をプロジェクトの初期構成としてコピーまたはクローンして利用します。

```bash
# 1. テンプレートのクローン
git clone https://github.com/oranie/ai-dev-setup.git my-new-project
cd my-new-project

# 2. ガードスクリプトのテスト実行
python3 -m unittest discover tests

# 3. 開発の開始
# Antigravity または Claude Code を起動すると、自動的に AGENTS.md / GEMINI.md / CLAUDE.md が読み込まれます。
```
