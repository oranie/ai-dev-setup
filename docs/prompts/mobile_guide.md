# モバイル短縮プロンプトガイド (docs/prompts/mobile_guide.md)

スマートフォンやタブレットなどのモバイル端末から操作する場合、長文の入力が難しく、プロンプトが単文・簡素になりがちです。
しかし、曖昧な単文（「全部治ってるの？」「続けて」等）をそのまま投げると、AIエージェントが全件走査や全選択肢の順次実行を始めてしまい、数十ターン（30分〜1時間）と数万トークンを浪費します。

短文でもAIを暴走させずに的確に動かすための「ショートコード」および「短縮記法ルール」です。

---

## 1. スラッシュコマンド（ショートコード）

指示の冒頭に以下のプレフィックスを付けることで、AI側があらかじめ定義された型で応答・展開します。

| コマンド | 展開される挙動 | 想定用途 |
| :--- | :--- | :--- |
| `/fix [対象] [現象]` | 影響範囲の事前調査メモを作成し、修正案を1つ提示して承認を待つ | ピンポイントのバグ修正 |
| `/feat [機能名]` | リファレンス調査 → 実装計画書（DoD付き）を作成し承認を待つ | 新機能の追加 |
| `/verify [対象]` | 単体テスト、環境差チェック、起動確認を実行してログを要約 | 変更後の動作確認 |
| `/triage` | 未解決課題の一覧を出し、着手すべき優先度順に番号付きで提示 | 作業方針の決定 |

---

## 2. 避けるべき単文と短縮代替構文

| 避けるべき指示 | 発生する問題 | 短縮代替構文 |
| :--- | :--- | :--- |
| 「全部治ってるの？」 | 範囲未定義のため全項目を洗い直し（実測34分・78ターン消費） | `[確認] 項目AとBの修正結果のみ教えて` |
| 「はい続けて」 | 提示された選択肢を順不同・全実行（実測60分・118ターン消費） | `[選択] 1で進めて` |
| 「マージして」 | マージ後のCI落ちやデプロイ失敗に気づけない | `[マージ] mainにマージしてCI成功まで確認して` |
| 「図を作って」 | Mermaidテキストか画像か粒度不明で往復（実測3往復） | `[画像] クラウド全体の構成図を画像で生成して` |

## 3. タグ付き短縮構文

モバイルからの入力時は、以下の角括弧タグを先頭に付与することで、AIエージェントにスコープと行動種別を即座に認識させます。

### `[調査]` タスク
コード生成を行わず、調査と技術メモの作成のみを指示する場合。
```text
[調査] Cloud Runの複数インスタンス起動時のSQLite競合についてdocs/references/にまとめて
```

### `[修正:スコープ限定]` タスク
変更対象のファイルを1つに絞って修正を指示する場合。
```text
[修正:backend/scoring.pyのみ] 欠損値はNaNで返し、他ファイルは変更しないで
```

### `[確認:項目限定]` タスク
特定の不具合や画面要素の修正状況だけを確認する場合。
```text
[確認:モーダル表示のみ] 画面幅375pxでの崩れが解消されたか教えて
```

### `[選択:番号]` 指示
AIが複数のアプローチを提示してきた際の回答。
```text
[選択] 案1を採用。進めてください
```

## 4. モバイル向け番号選択ルール
1. **逆質問には番号で回答する**: AIからの確認質問に対し、「了解」「適当に」ではなく「1」または「1と3」と返すだけで、推測による手戻りを防げます。
2. **重い作業はPC環境へ分離する**: ドメインルールの策定、新規アーキテクチャ導入、大規模リファクタリング等は、PC環境から詳細テンプレート（`docs/prompts/templates.md`）を用いて指示することを推奨します。
