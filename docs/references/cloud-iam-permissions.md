# クラウドIAM権限の調べ方（記入例）

> **このファイルは `template.md` の記入例です。** 実際に「記憶で断定して 403 を 2 回出した」
> ときの記録をもとにしています。内容は特定のクラウドに依存しますが、**調べ方と書き方**は
> どのプロジェクトでも同じです。自分のプロジェクトの1本目を書くときの見本にしてください。

- 調査日: 2026-09-15
- 参照元:
  - クラウド提供元の公式IAMリファレンス（ロール一覧と、各ロールに含まれる権限の一覧）
  - `gcloud iam roles describe` / `aws iam get-policy-version` 等、**実環境へ問い合わせるコマンド**
- 対象: 読み取り専用のサービスアカウントに、あるリソースの設定を読ませたい

## 1. 何を確かめたかったか

CI から参照専用の処理を動かすため、**必要最小限の権限だけを持つロール**を割り当てたかった。

## 2. 何を間違えたか（2回）

| 回 | 記憶に基づく判断 | 結果 |
|---|---|---|
| 1 | 「汎用の閲覧者ロールなら読めるはず」 | **403**。そのロールに当該の権限は含まれていなかった |
| 2 | 「レガシーな読み取りロールなら含むはず」 | **403**。これも含んでいなかった |

**2回とも、ロール名から中身を推測していた。** ロール名は中身を説明しません。

## 3. どう解決したか

3回目に、**ロールの中身を実際に列挙して数えた**。

```bash
# ロールに含まれる権限を、推測せずそのまま出す
gcloud iam roles describe roles/<ROLE_NAME> --format='value(includedPermissions)' \
  | tr ';' '\n' | grep <欲しい権限>

# どの既製ロールがその権限を含むかを総当たりで調べる
for r in $(gcloud iam roles list --format='value(name)'); do
  gcloud iam roles describe "$r" --format='value(includedPermissions)' \
    | grep -q '<欲しい権限>' && echo "$r"
done
```

分かったこと:

- その権限を含む既製ロールは **2つしかなかった**
- しかも**どちらも書き込み権限を同梱**していた
- つまり「読み取りだけ」を既製ロールで実現する方法は**存在しなかった**

→ 必要な権限だけを持つ**カスタムロール**を作って割り当てた。

## 4. 次に同じことをする人へ

- **ロール名から中身を推測しない。** 名前は中身を説明しない
- 403 が出たら、**エラーが名指ししている権限**をそのまま検索する。推測で別のロールを試すと、
  もう1回 403 を出すだけで終わる（実際そうなった）
- 「読み取りだけのロールがあるはず」という前提を疑う。**既製ロールに存在しない組み合わせは珍しくない**
- 調べた結果はこのディレクトリに残す。次の人が同じ2回を繰り返さずに済む
