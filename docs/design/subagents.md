# サブエージェント: 本体の会話に持ち込まないための設計

この文書は、**何を別コンテキストへ出し、何を手元に残すか**の設計と理由をまとめたものです。
運用ルールは [CLAUDE.md](../../CLAUDE.md) 3 節、ツール共通の原則は
[AGENTS.md](../../AGENTS.md) 2-A-9 にあります。

## 1. 何を解決するのか

**問題は 1 回のコストではなく、再送です。**

モデル API はステートレスで、毎回すべての会話履歴を送り直します。検証ログを 1 度会話に載せると、
そのセッションの残り全部のターンで再送され続けます。

```text
ターン1: テストを回す（2,000 行が会話に載る）
ターン2: +その分
ターン3: +その分
...     以降ずっと
```

会話に載りやすいものの例:

| 作業 | 会話に載る量の目安 |
|---|---|
| テストの全件実行 | 数百〜数千行 |
| ビルド・デプロイのログ | 数分ぶんの進行ログ |
| 生データや `node_modules` を含む grep | 検索語しだいで青天井 |
| 外部 API（Issue 一覧、検索結果）の生 JSON | 数万字になることがある |

サブエージェントは**会話履歴を引き継がない別コンテキスト**で動きます。生ログは向こうに閉じ、
本体には要約だけが返ります。再送されるのは要約の数十行だけになります。

## 2. 3 つの原則

### 原則 1: 判断は手元、実行は向こう

```text
その作業の出力は数百行を超えるか
├─ いいえ → 自分でやる（委譲の往復のほうが高い）
└─ はい  → 結果を見て判断や修正が要るか
           ├─ 要らない（調べて記録するだけ）→ 丸ごと委譲（reference-surveyor）
           └─ 要る → やることをプランに書き切れるか
                     ├─ 書き切れる   → 実装ごと委譲（implementer / implementer-lite）
                     └─ 書き切れない → 実行だけ委譲し、判断と修正は自分でやる（test-runner）
```

落ちたテストを直すには差分の文脈が要り、それは会話履歴にしかありません。渡そうとすると
結局すべてを渡すことになり、委譲の意味がなくなります。**書き切れないと感じたら、
委譲の粒度がまだ大きいという合図**です。

### 原則 2: 返すのは要約だけ

各 agent の本文に「返さないもの」を明記しています。指定しないと全部貼ってきます。

| agent | 返すもの | 返さないもの |
|---|---|---|
| `repo-scout` | パスと行番号、20 行以内 | ファイルの中身、grep の生出力、直し方の提案 |
| `test-runner` | 落ちたものだけ、30 行以内 | 成功したテストの一覧、スタックトレース全文、提案 |
| `reference-surveyor` | 書いたパスと結論 5 行 | 調査の生ログ（成果物はファイル） |
| `implementer` | 変更一覧、数字、**止めたところ**、30 行以内 | 差分の全文、生ログ |
| `implementer-lite` | 同上、20 行以内 | 同上 |

「直し方の提案」を返させないのは、**判断を手元に残す**ためです。向こうは会話履歴を持たないので、
提案に必要な文脈がありません。

### 原則 3: 書き込みは原則として手元

`repo-scout` と `test-runner` は `disallowedTools: Write, Edit, NotebookEdit` で
**書けないようにしてあります**。読むだけ、回すだけです。

書ける例外は 3 本だけです。

| agent | 持つもの | 範囲 |
|---|---|---|
| `reference-surveyor` | `Write` のみ | `docs/references/` に新規で書く |
| `implementer` | `Write` と `Edit` | **プランに書かれたファイルだけ**。コード生成を許す唯一の agent |
| `implementer-lite` | `Write` と `Edit` | **プランに書かれたファイルの、文書と定数だけ** |

「書ける agent はこの 3 本だけ」を `tests/test_subagents.py` で固定しています。
黙って 4 本目が増えるとテストが落ちます。

## 3. コンテキストの境界

何が渡り、何が渡らないかを把握していないと、委譲プロンプトが足りずに空振りします。

| 渡る | 渡らない |
|---|---|
| agent 本文（system prompt） | **会話履歴** |
| 委譲プロンプト（本体が書く） | 本体が読んだファイル、呼んだ skill |
| `CLAUDE.md` / `AGENTS.md` | 本体のモデルやコンテキスト窓（**向こうは自分のモデル基準**） |
| `skills:` に書いた skill の全文 | |

`reference-surveyor` が `skills: reference-survey` を指しているのは、**手順書を二重管理しないため**です。
skill を直せば向こうの挙動も変わります（AGENTS.md 2-A-5）。

## 4. モデルの選び方

- **エイリアス（`sonnet` 等）で書かない。** プロバイダによって解決先の世代が変わります。
  フル ID（`claude-sonnet-5`、`claude-opus-5-5`）で固定し、テストでも固定しています
- **検証を任せる相手を安く済ませても得はありません。** 安いモデルは終了コードや原因の切り分けを
  取り違えることがあり、`rc=0` を信じればそのまま次へ進んでしまいます
- 線は **「コードを生成するかどうか」**。生成しない作業に高いモデルの単価を払わない
- **`effort:` はまだ入れていません。** frontmatter では指定できますが、この 5 本で段階を振って
  測った数字がありません（AGENTS.md 2-A-8）。測ったら結果をここに書いてから入れます
- 委譲先は本体とモデルが違うので、本体のプロンプトキャッシュを共有しません
  （`docs/references/claude-platform-cost.md`）

## 5. 安全装置はどこで効くか

**hook はサブエージェントの中でも走ります。** 委譲しても遮断は迂回されません。

| 層 | 何を止めるか |
|---|---|
| `tools:` / `disallowedTools:` | そもそも書き込ませない（`repo-scout` / `test-runner`） |
| `guard_bash.py`（PreToolUse） | 取り返しのつかない Bash |
| `big_output.py`（PostToolUse） | 止めない。大きい出力を受けたことを知らせるだけ |
| 設計 | 本番操作・PR・マージは委譲しない |

`tools` の指定だけに頼らないのは、`disallowedTools` では細かく絞れないからです。
`Bash(git push *)` と書くと Bash ごと落ちます。「push だけ止める」は hook の仕事です。

## 6. Antigravity との関係

サブエージェントは **Claude Code 固有の機能**です。Antigravity 側に同じ仕組みはありません。
向こうで作業するときは文脈の圧縮をハーネスに任せ、出力の絞り込みとスクラッチの隔離だけを守ります
（[GEMINI.md](../../GEMINI.md) 1-3）。

共有している skill の本文に道具名を書くときは、**「Claude Code なら `test-runner`」と条件付きで**
書いてください。道具名だけ書くと、Antigravity 側では空振りの指示になります。

## 7. 足すとき

1. `.claude/agents/<名前>.md` を書く（`name` と `description` が必須）
2. `description` に**いつ使うか**を書く。呼ぶかどうかはこれを見て決まる
3. `model` は**フル ID で固定**する
4. 返すもの・返さないものを本文に明記する
5. `CLAUDE.md` 3 節の表に 1 行足す（テストが見張っています）
6. `tests/test_subagents.py` の `EXPECTED` に足す。書き込める agent なら `WRITABLE` にも
   （**黙って緩めない**。増やす理由をこの文書の原則 3 に書く）
7. **セッションを開き直す。** agent は起動時に読み込まれます

## 8. やらないと決めたこと

| やらないこと | 理由 |
|---|---|
| 本番操作・PR・マージの委譲 | 取り返しがつかない。手元に残す |
| 軽い作業の委譲 | 向こうは規約を読み直すところから始まる。往復のほうが高い |
| 出力の小さい作業のための agent | 委譲する意味がない |
